LangChain

El andamiaje entre un modelo de lenguaje y una aplicación real

El problema: un LLM solo no basta

Un modelo de lenguaje, por potente que sea, tiene cuatro límites estructurales:

No conoce tus datos

Su conocimiento terminó en la fecha de corte del entrenamiento. Tu informe de la semana pasada no existe para él.

No puede actuar

No consulta una API, no lee un archivo, no ejecuta un cálculo. Solo genera texto.

No recuerda

Cada llamada es independiente. La "conversación" es una ilusión que construye la aplicación.

Alucina con seguridad

Cuando no sabe, inventa — y lo hace con el mismo tono de confianza que cuando acierta.

Los cuatro límites se atacan con las mismas dos ideas: darle contexto recuperado (RAG) y darle herramientas (agentes). LangChain es el pegamento.

Qué es LangChain

Un framework de orquestación: estandariza cómo se conectan modelos, fuentes de datos y herramientas, para que cambiar una pieza no obligue a reescribir la aplicación.

Abstracción

La misma interfaz para OpenAI, Anthropic, Ollama o Hugging Face. Cambiar de modelo es cambiar una línea.

Composición

Piezas pequeñas que se encadenan: prompt → modelo → parser → herramienta.

Integraciones

Cientos de conectores ya escritos: PDFs, Notion, SQL, y ~40 bases vectoriales.

No es un modelo ni una base de datos. Es la tubería que los une.

LCEL: componer con |

LangChain Expression Language usa el operador de tubería para encadenar pasos. Cada pieza recibe la salida de la anterior:


from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_ollama import ChatOllama

prompt = ChatPromptTemplate.from_template(
    "Resume en una frase: {texto}"
)
modelo = ChatOllama(model="qwen2.5:7b", base_url="http://ollama:11434")

cadena = prompt | modelo | StrOutputParser()

cadena.invoke({"texto": "..."})          # síncrono
await cadena.ainvoke({"texto": "..."})   # asíncrono, gratis
cadena.batch([{...}, {...}])             # en lote, paralelizado
for token in cadena.stream({...}): ...   # streaming token a token

Lo importante: invoke, stream, batch y sus versiones async salen gratis al componer con |. No hay que implementarlas.

Herramientas: darle manos al modelo

Una herramienta es una función de Python. El docstring no es decorativo: es el texto que el modelo lee para decidir si la usa.


from langchain_core.tools import tool

@tool
def buscar_en_documentos(consulta: str) -> str:
    """Busca información en la base de datos vectorial del usuario.

    Úsala SIEMPRE que la pregunta se refiera al contenido de los
    documentos, informes o PDFs que el usuario haya cargado. Es la
    única forma de acceder a esa información.

    Args:
        consulta: La pregunta a buscar, en lenguaje natural.
    """
    resultados = store.similarity_search_with_score(consulta, k=4)
    ...

Buen docstring

Dice cuándo usarla y qué la hace única. El modelo acierta.

Mal docstring

"Busca cosas." El modelo la ignora o la usa fuera de lugar.

Insistir aquí: el 80% de los fallos de un agente que "no usa las herramientas" se arreglan reescribiendo docstrings, no cambiando de modelo.

Cadena vs. Agente

La distinción más importante de toda la sesión — y la que más se confunde.

Cadena (chain)Agente (agent)
FlujoFijo, lo escribes túDinámico, lo decide el modelo
PasosSiempre los mismosVariables según la pregunta
EjemploBuscar → responder, siempre¿Busco? ¿Calculo? ¿Ambos? ¿Ninguno?
Coste1 llamada al LLMN llamadas (una por iteración)
PrevisibleAltaMedia
FlexibleBajaAlta

Regla práctica: si siempre haces los mismos pasos, usa una cadena. El agente solo se justifica cuando el camino depende de la pregunta.

El bucle ReAct

Es lo que ejecuta create_react_agent por dentro. ReAct = Reasoning + Acting.

Pregunta"¿Cuánto suman los costes del informe?"
→
Modelo razona"Necesito los datos: uso buscar_en_documentos"
→
Ejecuta la toolDevuelve 4 fragmentos con cifras
Modelo razona"Ahora sumo: uso calculadora"
→
Ejecuta la tool1250 + 3400 = 4650
→
RespondeCon la cifra y la cita de la fuente

El bucle termina cuando el modelo responde sin pedir más herramientas. Conviene poner un tope de iteraciones: un agente mal instruido puede quedarse dando vueltas.

El ecosistema

LangChain

Los componentes y las integraciones. El punto de partida.

Cadenas lineales, retrievers, loaders.

LangGraph

Flujos como grafo de estados: ciclos, ramas, puntos de control, intervención humana.

Es lo que usamos para el agente.

LangSmith

Observabilidad: traza cada llamada, mide latencia y coste, evalúa calidad.

Opcional y de pago; no lo usamos aquí.

Alternativas del mercado: LlamaIndex (más centrado en indexación y RAG), Haystack (pipelines de búsqueda), o directamente el SDK del proveedor si el caso es simple.

Embeddings y bases vectoriales

Cómo se busca por significado y no por palabras

El límite de la búsqueda por palabras

Un buscador tradicional compara cadenas de texto. Si el usuario pregunta:

«¿Cómo reduzco el gasto energético de la planta?»

…un documento que dice «optimización del consumo eléctrico de la instalación» es la respuesta perfecta — y no comparte ni una palabra clave.

Necesitamos comparar significados, no caracteres. Para eso hay que convertir el texto en algo que se pueda medir: números.

Qué es un embedding

Un modelo de embeddings convierte un texto en un vector: una lista de números que codifica su significado.


embeddings = OllamaEmbeddings(model="nomic-embed-text")

v = embeddings.embed_query("El gato duerme en el sofá")

len(v)    # 768  -> 768 dimensiones
v[:5]     # [0.0231, -0.0417, 0.0128, 0.0093, -0.0356]

Cada dimensión no tiene un nombre legible. Lo que importa es la posición relativa: textos con significado parecido caen cerca unos de otros en ese espacio de 768 dimensiones.

Regla crítica: el mismo modelo debe usarse para indexar y para consultar. Dos modelos distintos generan espacios incompatibles y las distancias dejan de significar nada.

El espacio vectorial

Medir la cercanía

Coseno

Mide el ángulo entre vectores, ignorando su longitud. Un texto largo y uno corto sobre el mismo tema salen cercanos.

El estándar de facto en NLP.

Euclidiana (L2)

Distancia en línea recta. Sensible a la magnitud del vector. Equivale al coseno si los vectores están normalizados.

Es la que usa Chroma por defecto.

Producto interno

El más rápido de calcular. Requiere vectores normalizados para comportarse bien.

Común en catálogos muy grandes.

Ojo con el signo: Chroma devuelve distancia, no similitud. menor = más parecido — al revés de lo que sugiere la palabra «score».

Por qué hace falta un índice

Con 1 000 fragmentos, comparar la consulta contra todos es instantáneo. Con 10 millones, no.

Fuerza bruta (flat)

Compara con los N vectores. Exacto pero lineal: el tiempo crece con el corpus.

Bien hasta ~100 000 vectores.

Búsqueda aproximada (ANN)

Renuncia a la garantía de exactitud a cambio de una búsqueda casi logarítmica.

Recupera ~95-99% de los vecinos reales, cientos de veces más rápido.

HNSW es el algoritmo más usado (y el de Chroma): construye un grafo por capas donde las capas superiores tienen conexiones largas para «saltar» a la zona correcta, y las inferiores conexiones cortas para afinar. Es como un mapa de rutas: primero la autopista, luego la calle.

Qué es realmente una base vectorial

No es solo un archivo de vectores. Es un motor con cuatro responsabilidades:

AlmacenarVectores + el texto original + metadatos
·
IndexarEstructuras ANN (HNSW, IVF) para buscar rápido
·
FiltrarCombinar similitud con condiciones sobre metadatos
·
PersistirSobrevivir a reinicios, escalar, replicar

El filtrado por metadatos es lo que la hace útil en producción — «busca en documentos de 2026, del departamento de ingeniería, que este usuario pueda ver»:


store.similarity_search(
    "consumo energético",
    k=4,
    filter={"fuente": "informe_ISA.pdf"},   # filtro sobre metadatos
)

RAG

Retrieval-Augmented Generation: juntar las dos mitades

El pipeline completo

Fase 1 — Indexación (una vez, o cada vez que cambian los documentos)

CargarPDF, DOCX, TXT → texto plano
→
FragmentarTrozos de ~1000 caracteres
→
EmbeberCada trozo → vector de 768 dims
→
AlmacenarVector + texto + metadatos en Chroma

Fase 2 — Consulta (en cada pregunta)

PreguntaSe convierte en vector con el mismo modelo
→
RecuperarLos k fragmentos más cercanos
→
AumentarSe inyectan en el prompt como contexto
→
GenerarEl LLM responde citando la fuente

El modelo nunca se reentrena. Solo se le da mejor contexto — por eso RAG es tan barato comparado con un fine-tuning.

Fragmentar: el parámetro que más importa

Es donde se gana o se pierde la calidad del sistema, y casi nadie le dedica tiempo.

Fragmento demasiado grande

  • El vector «promedia» varios temas
  • La búsqueda pierde precisión
  • Se gasta contexto en texto irrelevante

Fragmento demasiado pequeño

  • Se pierde el contexto necesario
  • Las referencias quedan huérfanas («esto», «dicho valor»)
  • Hacen falta más fragmentos para responder

splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,      # ~250 palabras: un párrafo largo
    chunk_overlap=150,    # solapamiento: evita cortar una idea por la mitad
    separators=["\n\n", "\n", ". ", " ", ""],  # se intenta en este orden
)

Recursive significa que intenta cortar primero por párrafos, luego por líneas, luego por frases, y solo al final por caracteres sueltos — así respeta la estructura del texto.

Por qué contenedores separados

Cada servicio escala y se reinicia por su cuenta. Los modelos viven en un volumen: recrear la app no obliga a bajar 5 GB otra vez.

Privacidad total

Ningún dato sale de la máquina. Ni el documento, ni la pregunta, ni la respuesta. Relevante para información confidencial.

La ingesta


# 1. Cargar — un loader por tipo de archivo
documentos = PyPDFLoader(str(ruta)).load()   # un Document por página

# 2. Fragmentar
splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=150)
fragmentos = splitter.split_documents(documentos)

# 3. Metadatos: sin esto no se puede citar ni filtrar
for i, fragmento in enumerate(fragmentos):
    fragmento.metadata["fuente"] = fuente
    fragmento.metadata["fragmento"] = i

# 4. Reingesta idempotente: borrar lo viejo de este archivo antes de insertar
store._collection.delete(where={"fuente": fuente})

# 5. Embeber y almacenar — aquí es donde se llama al modelo de embeddings
store.add_documents(fragmentos)

El paso 4 es el que evita que ejecutar la ingesta dos veces duplique todo el corpus — un error clásico que degrada la búsqueda en silencio.

El agente


from langgraph.prebuilt import create_react_agent
from langchain_ollama import ChatOllama

llm = ChatOllama(
    model="qwen2.5:7b",
    base_url="http://ollama:11434",
    temperature=0.1,          # bajo: en RAG queremos fidelidad, no creatividad
)

agente = create_react_agent(llm, HERRAMIENTAS)

resultado = agente.invoke({"messages": [
    SystemMessage(content=INSTRUCCIONES),
    *historial[-20:],         # memoria recortada: el contexto es finito
    HumanMessage(content=pregunta),
]})

respuesta = resultado["messages"][-1].content

Qwen 2.5 soporta tool calling nativo, que es justo lo que el bucle ReAct necesita. Un modelo sin esa capacidad obligaría a un ReAct por texto plano, mucho más frágil.

Limitaciones honestas

Velocidad en Docker sobre Mac

Los contenedores no acceden a la GPU (Metal). Qwen 7B corre en CPU: funciona, pero responde en decenas de segundos. Para demos en vivo, qwen2.5:3b va unas 3× más rápido.

Calidad vs. modelos grandes

Un modelo local de 7B razona peor que GPT-4 o Claude. A cambio: privacidad total, coste cero por consulta y funcionamiento sin conexión.

RAG no es magia

Si la respuesta no está en los documentos, o la fragmentación la partió mal, el sistema no la encontrará. La calidad del corpus manda.

Sin OCR

Los PDF escaneados no producen texto extraíble. Habría que añadir una etapa de OCR antes de la ingesta.

Si quieres llevarlo más lejos

Búsqueda híbrida

Combinar BM25 (léxico) con vectores. Recupera mejor los nombres propios, códigos y siglas, que los embeddings manejan mal.

Reranking

Recuperar 20 fragmentos y reordenarlos con un cross-encoder, quedándose con los 4 mejores. Suele ser la mejora con mejor relación esfuerzo/resultado.

Evaluación

Un conjunto de preguntas con respuesta conocida para medir si un cambio mejora o empeora. Sin esto, se optimiza a ciegas.

Interfaz web

Un Streamlit o FastAPI como contenedor adicional, hablando con los mismos servicios.

Para recordar

1. LangChain no es un modelo: es la orquestación entre modelos, datos y herramientas.

2. Un embedding convierte significado en posición. Buscar pasa a ser medir distancias.

3. Una base vectorial es un índice ANN + filtrado por metadatos, no un archivo de números.

4. RAG le da contexto al modelo; un agente le da decisiones. Son cosas distintas y se combinan.

5. La calidad de un RAG se decide en la fragmentación y en la calidad del corpus, no en el tamaño del modelo.
